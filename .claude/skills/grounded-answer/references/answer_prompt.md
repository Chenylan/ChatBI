# 可粘贴的防幻觉提示词模板

把下面这段追加到数据 Agent 的系统提示词里（本项目对应 `agent.py` 的 `sys_msg`）：

```text
IMPORTANT — 最终答案的呈现格式（用于防止凭空编造数据）：
每次回答数据类问题时，最终答案必须按以下顺序分节列出，缺一不可：
1. 数据来源表：列出本次查询实际用到的表名（FROM / JOIN 涉及的所有表）。
2. 计算过程：粘贴你实际执行、且由 execute_sql_query 工具返回的 SQL 语句。
3. 查询结果：列出工具返回的原始数据（关键行或数值）。
4. 结论：基于上述结果得出的解读。
硬性要求：
- 结论中的每一个数字都必须能追溯到第 3 步的查询结果，禁止编造查询结果之外的数字。
- 若查询没有返回数据（rows 为空），必须明确说明"没有查到数据"，不得编造结果。
- 禁止输出"让我执行SQL查询…"这类只描述不做事的占位语；一旦需要查数，必须立刻调用执行工具。
```

## 落到不同工具时的替换规则

- `execute_sql_query` 换成你实际的执行工具名（如 `run_sql` / `db_query`）。
- 如果项目还有 RAG schema 工具，可补一条：生成 SQL 前先调用 schema 检索工具确认表名/列名，不要凭记忆编。

## 为什么这样写有效

- 「四段式」把 grounding 变成**格式要求**，模型不按格式就过不了，编造数字会立刻暴露在「结论 vs 查询结果」的对照里。
- 「粘贴工具返回的 SQL」堵住「模型脑补一条 SQL 但实际没执行」的空转。
- 「空结果明说」针对模型在查不到时倾向于硬造一个"合理"数字的已知倾向。

# 防幻觉落地答案（Grounded Answer）

目标：让 LLM 数据 Agent 回答里的**每一个数字都能追溯到工具真实返回的查询结果**，从流程上堵死「凭空编造答案」和「把相近口径的历史数据当当前结果」两类幻觉。

核心手段：**用输出格式倒逼 grounding**——强制模型在最终答案里列出「来源表 + 实际执行的 SQL + 原始结果 + 结论」，结论中的数字必须来自第 3 步，编造就无处遁形。

## 四段式强制格式（直接写进系统提示词）

完整可粘贴的提示词模板见 [references/answer_prompt.md](references/answer_prompt.md)，骨架如下，四段缺一不可：

1. **数据来源表**：本次查询实际用到的表（`FROM` / `JOIN` 涉及的所有表）。
2. **计算过程**：粘贴**实际执行、且由执行工具返回**的 SQL——不是"我准备执行的 SQL"，而是工具回显的那条。
3. **查询结果**：列出工具返回的原始数据（关键行或数值）。
4. **结论**：基于上述结果的解读。

## 三条硬性规则（必须一起写进提示词，缺一条就防不住）

- **数字可追溯**：结论里的每个数字必须能追溯到第 3 步的查询结果，禁止编造查询结果之外的数字。
- **空结果必须明说**：`rows` 为空时明确写「没有查到数据」，不得编造结果（模型很容易在查不到时硬造一个"合理"数字）。
- **必须真的调工具**：禁止输出"让我执行 SQL 查询…"这类只描述不做事的占位语，一旦需要查数必须立刻调用工具。

## 配套：把「回显 SQL」打通（关键前提）

光写格式不够，还得让模型拿得到「真实执行的 SQL」。执行工具的成功返回必须带 `query` 回显字段，例如：

```python
return {"status": "success", "result": {"query": query, "columns": columns, "rows": rows}}
```

这样最终答案的「计算过程」段贴的才是模型真正跑过的那条 SQL，而不是模型脑补的一条。本项目对应 [tools/tools_execute_sqlite.py:316-317](../../../tools/tools_execute_sqlite.py#L316-L317)。

## 评审/自测清单（发现幻觉的检查点）

1. 结论里的每个数字，能不能在「查询结果」段找到对应行？
2. 「计算过程」段贴的 SQL，和工具回显的 SQL 是否一致（不是模型重写的）？
3. 查询结果为空时，答案是否老老实实写了「没有查到数据」？
4. 有没有出现查询结果里根本没有的表名 / 列名 / 数字？
5. 涉及"当前值"的问题，是否混入了历史数据当当前结果？（这是 RAG 召回/记忆层的另一类幻觉，需配合「召回加相似度阈值 + 记忆带时间戳」一起防，见下文）

## 相关幻觉向量（本 skill 之外还需处理的）

本 skill 只堵「最终答案不落地」这一条。完整防幻觉还要叠加：

- **RAG 召回无阈值**：向量"近邻召回"可能把相似但不相关的内容塞进上下文 → 加相似度阈值。
- **记忆无时间戳**：把旧结论当当前结果 → 记忆事实带时间戳 + 新鲜度衰减。
- **text2sql 未校验 schema**：模型凭记忆编表名/列名 → 生成 SQL 前用 schema RAG 校验。
